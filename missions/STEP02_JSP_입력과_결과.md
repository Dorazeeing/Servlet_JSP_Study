# STEP 2 — JSP 입력과 결과

> 원본: `practice/06_02/source_code/custom_project`의 `input.jsp`, `result.jsp` · 실습 지시서: `practice/06_02/06_02_01~06`
> **원본 두 파일은 다 쓸 때까지 열지 않습니다.**

## 목표

서블릿 없이 **JSP 두 개**만으로, 폼에서 보낸 값을 받아 화면에 보여 주고 세션에 저장합니다.
이 과정에서 네 요소를 직접 써 봅니다: **지시어 / 스크립틀릿 / 표현식 / 내장 객체(`request`, `session`)**

STEP 1과 같은 **파라미터 계약**(폼의 `name` 속성 ↔ 서버의 `getParameter` 키)이 그대로 이어집니다.
달라진 것은 받는 쪽입니다. `@WebServlet`으로 주소를 연결하던 자리에, 이번에는 **파일 이름이 곧 주소**입니다.

## 작업 순서

| 순서 | 파일 | 하는 일 | 이 순서인 이유 |
|---|---|---|---|
| 1️⃣ | `input.jsp` | 폼을 만든다 | 폼의 `name` 속성이 **계약(키)** 을 정한다 |
| 2️⃣ | `result.jsp` | 그 키를 읽고 출력한다 | 키는 1️⃣에서 이미 정해졌다 |
| 3️⃣ | (실행) | 두 파일을 서버에서 확인한다 | 둘 다 있어야 요청이 왕복한다 |

두 파일 모두 `src/main/webapp/` 바로 아래에 둡니다. (`WEB-INF`가 아닙니다. 브라우저가 주소로 직접 열어야 하기 때문입니다.)

---

## 2-1. `input.jsp` — 폼

| 항목 | 값 |
|---|---|
| 페이지 설정 | `contentType`은 `text/html; charset=UTF-8`, `pageEncoding`은 `UTF-8` |
| `<title>` | `JSP Input` |
| `<h1>` | `JSP 입력` |
| 폼 | `action="result.jsp"`, `method="post"` |
| 입력칸 ① | `name="name"` (라벨: 이름) |
| 입력칸 ② | `name="message"` (라벨: 메시지) |
| 버튼 | `전송` |

- 모양은 자유입니다. STEP 1에서 쓴 `assets/css/style.css`를 링크해도 됩니다.
- 이 파일에는 자바 코드가 **지시어 한 줄뿐**입니다.

## 2-2. `result.jsp` — 받아서 보여 주기

파일 안에서 **위에서 아래로** 이 순서입니다.

| 순서 | 구문 | 할 일 |
|---|---|---|
| ① | 지시어 | 2-1과 같은 페이지 설정 |
| ② | 스크립틀릿 | 요청 인코딩을 `UTF-8`로 지정 |
| ③ | 스크립틀릿 | `name`, `message` 파라미터를 문자열 변수로 받는다 |
| ④ | 스크립틀릿 | 세션에 **키 `loginName`**, 값 `name`으로 저장한다 |
| ⑤ | HTML + 표현식 | `<h1>요청 결과</h1>`, 그 아래 세 줄을 출력한다 |

⑤의 세 줄은 이렇습니다.

| 줄 | 출력할 것 |
|---|---|
| 이름: | 변수 `name` |
| 메시지: | 변수 `message` |
| 세션 이름: | **세션에서 꺼낸** `loginName` (변수를 그대로 쓰지 않는다) |

- `<title>`은 `JSP Result`입니다.
- ②가 ③보다 앞이어야 하는 이유는 STEP 1의 `doPost`와 같습니다.
- 마지막 줄을 변수가 아니라 **세션에서 꺼내라고** 하는 이유가 있습니다. 직접 해 보고 나서 질문으로 확인합니다.

## 필요한 함수와 구문

JSP에서는 **선언 없이 쓸 수 있는 객체**가 있습니다. 스크립틀릿 안에서 `request`, `session`이라고만 쓰면 됩니다. (서블릿에서는 `req`를 매개변수로 받았지만, 여기서는 받는 코드가 없습니다.)

| 종류 | 이름 | 쓰임 |
|---|---|---|
| 지시어 | `<%@ page contentType="..." pageEncoding="..." %>` | 파일 맨 위. 문자 인코딩과 응답 타입을 정한다 |
| 스크립틀릿 | `<% 자바 문장; %>` | 자바 코드를 **실행**한다. 화면에는 아무것도 쓰지 않는다 |
| 표현식 | `<%= 값 %>` | 값을 **그 자리에 출력**한다. 끝에 세미콜론을 붙이지 않는다 |
| 내장 객체 | `request` | 요청 정보. STEP 1의 `req`와 같은 종류다 |
| 내장 객체 | `session` | 같은 브라우저에서 이어지는 요청들이 **함께 쓰는 저장소** |
| 요청 | `request.setCharacterEncoding(String)` | 파라미터를 읽기 **전에** 호출한다 |
| 요청 | `request.getParameter(String)` → `String` | 키가 없으면 `null` |
| 세션 | `session.setAttribute(String 키, Object 값)` | 세션에 저장한다 |
| 세션 | `session.getAttribute(String 키)` → `Object` | 세션에서 꺼낸다. 키가 없으면 `null` |

## 확인

서버를 실행하고 **먼저 예측을 적은 뒤** 확인합니다. (`http://localhost:8080/input.jsp`)

| 요청 | 예측 | 관측 |
|---|---|---|
| 이름 `홍길동`, 메시지 `안녕`을 입력하고 전송 — 주소창의 파일명과 세 줄 |  |  |
| 이름과 메시지를 **비운 채** 전송 — 세 줄 |  |  |
| 주소창에 `localhost:8080/result.jsp`를 **직접** 입력해서 열기 — 세 줄 |  |  |
| `input.jsp`를 열고 **브라우저에서 소스 보기** — `<% %>`가 보이는가 |  |  |

> JSP 파일을 탐색기에서 더블클릭해 브라우저로 열면 서버를 거치지 않아 `<% %>`가 그대로 보이거나 다운로드됩니다. **반드시 서버 주소로** 엽니다.

## 생각해 볼 질문

STEP 2 리뷰 때 물어봅니다.

1. STEP 1의 `/hello`와 이번 `/result.jsp`에서 **주소가 서버 코드와 연결되는 방식**은 어떻게 다릅니까?
2. `<%@ %>`, `<% %>`, `<%= %>`는 각각 **무엇을 하고**, 화면에 **무엇을 남깁니까**?
3. `result.jsp`를 주소창으로 직접 열면 세 줄은 각각 무엇이 나옵니까? 그 이유는 무엇입니까?
4. `result.jsp`가 서버에서 실행되는 동안 **내부적으로 무엇으로 바뀌어** 실행됩니까?
5. 이름 줄과 세션 이름 줄은 값이 같은데, 값이 **온 경로**는 어떻게 다릅니까?

## 완료 기준

- [ ] `input.jsp`의 폼이 `result.jsp`로 POST를 보낸다
- [ ] 한글 이름과 메시지가 깨지지 않고 세 줄에 나온다
- [ ] `세션 이름` 줄은 `session.getAttribute`로 꺼낸 값이다
- [ ] 확인 표의 예측과 관측 칸을 채웠다
- [ ] 다 쓴 뒤 원본 `input.jsp`, `result.jsp`와 대조해 다른 점을 찾았다

끝나면 **"STEP 2 끝"** 이라고 말하세요. 코드를 읽고 리뷰한 뒤 STEP 3(세션 로그인)을 드립니다.

기본 요구를 통과한 뒤에, 아래를 **하나씩** 더합니다. 한 번에 다 하지 않습니다.

| 순서 | 추가할 것 | 새로 알게 되는 것 |
|---|---|---|
| ① | 이름이 `null`이거나 공백뿐이면 대체 문구(예: `이름없음`)를 쓴다 | 빈 문자열은 `null`이 아니다 (STEP 1과 같은 판단) |
| ② | 입력칸 `age`를 추가하고, 비어 있으면 `0`, 아니면 숫자로 바꿔 쓴다 | 문자열 `""`는 숫자로 바꾸면 예외가 난다 |
| ③ | 체크박스 `hobby`(독서·코딩·음악) 셋을 추가하고, 고른 것을 나열한다 | 같은 키로 값이 여러 개 온다. 하나도 안 고르면 키 자체가 없다 |
